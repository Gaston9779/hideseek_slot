## 1. Simultaneous triggers

### Exact enumeration

The base game has `96⁵ = 8,153,726,976` equiprobable stop combinations. [exact.ts](../tools/math/v3/exact.ts) builds the exact bivariate distribution of visible Scatter and Chest Bonus counts by enumerating every three-symbol reel window and convolving the five reel distributions with integer arithmetic.

| Base event | Exact combinations | Exact probability | One in |
|---|---:|---:|---:|
| 3+ Scatter | 58,091,094 | `119529/16777216` = 0.7124483585% | 140.3611 |
| 3+ Chest Bonus | 2,373,138 | `4883/16777216` = 0.0291049480% | 3,435.8419 |
| Both on the same spin | 868,572 | `24127/226492416` = 0.0106524538% | **9,387.5084** |

The proportion of Chest triggers that are simultaneous is therefore:

`P(dual | chest) = 868,572 / 2,373,138 = 48,254 / 131,841 = 36.6001471469%`.

This is not the sum of separate feature events. The numerator contains only base grids whose same 5×3 window has both counters at or above three.

### Concrete reproducible outcome

Audit PRNG seed `693` produces base stops `[75, 11, 13, 21, 16]`:

| Reel | Top | Middle | Bottom |
|---:|---|---|---|
| 1 | SCATTER | GHOST | POTION |
| 2 | WILD | GHOST | CHEST_BONUS |
| 3 | GHOST | CHEST_BONUS | SCATTER |
| 4 | KEY | CHEST | MAUSOLEUM |
| 5 | CHEST_BONUS | SCATTER | GHOST |

The production evaluator returns exactly three Scatters, three Chest Bonus symbols, 3.9× ordinary/Scatter award, 12 committed Free Spins and a committed chest set `[10,24,40]`. The engine emits one `DUAL_BONUS_TRIGGERED`, not separate base `FREE_SPINS_TRIGGERED` and `CHEST_BONUS_TRIGGERED` events.

### Counter scope

- `generateOutcome()` can create a chest only when `mode === 'base'`.
- Every dedicated Free Spin strip contains zero `CHEST_BONUS` stops.
- The Monte Carlo trigger counters are incremented only inside the `o.mode === 'base'` branch. Free Spin retriggers increase the physical-spin and feature counters but never the paid-round simultaneous counter.
- The 100M production-engine run observed 10,633 simultaneous base triggers, consistent with the exact 1/9,387.5084 rate.

Result: **PASS**.

## 2. Max Win 5,000×

### Exact rule and probability

The 5,000× value exists only in the weighted Chest Bonus set `[100,500,5000]`. It is not generated by a special Free Spins rule or an invisible draw. The set has weight `340/10,000 = 17/500`; its three values are uniformly shuffled before the click, so any fixed valid selection finds 5,000× with probability `1/3` conditional on that set.

`P(5000 selected | Chest) = (17/500) × (1/3) = 17/1500 = 1.1333333333%`.

`P(5000 selected per paid round) = (4883/16777216) × (17/1500)`

`= 83011/25165824000 = 0.0003298560778% = 1 in 303,162.5207`.

The jackpot is therefore commercially observable: the 100M run produced 335 selections against an expectation of approximately 329.856.

### RTP contribution

| Component | RTP contribution |
|---|---:|
| Selected 5,000×, gross | 1.6492803891% |
| Exact jackpot-round cap correction | −0.0063124399% |
| **Selected 5,000×, net** | **1.6429679492%** |
| All non-jackpot chest selections | 1.4564504067% |
| **Chest Bonus net total** | **3.0994183560%** |

The correction removes base awards already present and Free Spins that are forfeited when the same logical paid round reaches its 5,000× cap. This prevents the jackpot event from being counted as 5,000× plus feature value. Non-jackpot accumulation into the cap changes RTP by less than `4.703×10⁻⁴⁷`, per [non-jackpot-cap-bound.json](data/v3/non-jackpot-cap-bound.json).

### Visibility and single payment

Seed `295476` generates stops `[92,13,12,14,1]`, three Chest Bonus symbols and committed prizes `[100,500,5000]`. The real browser selected index 2 and verified:

- the bonus summary visibly contained `5000×` and `BEST PICK`;
- the paytable lists the `100/500/5,000×` set;
- at 100-cent stake the balance followed `100,000 − 100 + 500,000 = 599,900` cents;
- a second pick is rejected because `selected !== null`;
- the client received one `BEST_CHEST_PICK` and one `MAX_WIN` event.

Result: **PASS**.

## 3. Production consistency and complete RTP split

### Build-to-model trace

The production import chain is explicit:

- [config/game.ts](../src/config/game.ts) re-exports V3 symbols, bets, paylines and max win.
- [math/evaluate.ts](../src/math/evaluate.ts) and [math/slot.ts](../src/math/slot.ts) re-export V3 evaluation/outcome code.
- [engine/game.ts](../src/engine/game.ts) imports V3 configuration and `generateOutcome()` directly.
- The production bundle contains the 96-stop V3 arrays, the Chest Bonus sets and all five event names.
- The complete strip/configuration payload matches the pinned SHA-256 above.

`CHEST`, `SCATTER` and `CHEST_BONUS` are separate symbol IDs and separate art mappings. `CHEST` is a normal line symbol. `SCATTER` pays and awards Free Spins. `CHEST_BONUS` has zero line pay and only commits Hide & Seek on 3+ visible symbols.

### RTP without double counting

| Mutually accounted component | RTP |
|---|---:|
| Base line wins | 58.0239754032% |
| Base Scatter wins | 2.8026401997% |
| **Base total** | **60.8266156029%** |
| Free Spins, including retriggers | 32.0746149179% |
| Chest selections excluding 5,000× | 1.4564504067% |

| **Chest net total** | **3.0994183560%** |

There is deliberately no extra “simultaneous RTP” row: simultaneous rounds are an overlap of trigger conditions, not a third payout. Their base, Scatter, Free Spin and chest values are already present once in the relevant rows. Settlement order is base award → chest pick → Free Spins; the idempotent settlement flag and chest selection guard prevent duplicate credits.

Exactly plus above equals the previously reported 16.715680% probability of returning at least the stake. Conservation failures remained zero and all other 100M results were unchanged.

Result: **PASS**.

## 4. Presentation-event contract

The new non-economic contract is [events.ts](../src/engine/events.ts). The browser dispatch name is `skull-hunt:game-event`; `CustomEvent.detail` is one of:

| Event | Reliable committed condition |
|---|---|
| `FREE_SPINS_TRIGGERED` | Base Scatter award or Free Spin retrigger; payload distinguishes `BASE` and `RETRIGGER` |
| `CHEST_BONUS_TRIGGERED` | Base spin committed a chest without a simultaneous Free Spins award |
| `DUAL_BONUS_TRIGGERED` | The same base grid committed both features; emitted instead of two separate base-trigger events |
| `MAX_WIN` | `capReached` changed from false to true |
| `BEST_CHEST_PICK` | The single accepted committed pick equals the maximum value in its set; ties qualify |

Events are queued in the engine, included in version-matched snapshots until drained, dispatched by the client after committed settlement/pick, and cannot repeat after a second settle or pick. No animation consumes these events yet.

Unit tests cover mutual exclusivity, retrigger labelling, snapshot restore, best pick, max transition and double-drain/double-pick. Real browser QA received all five event types, including `DUAL_BONUS_TRIGGERED` for seed 693 and `MAX_WIN` for seed 295476.

Result: **PASS**.

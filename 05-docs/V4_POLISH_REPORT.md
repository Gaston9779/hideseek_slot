# V4 polish — spin continuity, anticipation, control bar, numeric centring

Presentation only. Math V3 (strips, RNG, paytable, bonuses, RTP 96.0006488767 %) untouched; `git diff` of `src/math`, `src/engine` is empty for this task.

## 0. Priority fix — reel spin continuity
**Real cause (reproduced on the old code with a recording-canvas harness, first frame after the click):** `Reels.draw()` built every moving strip from a pseudo-random filler table (`FILLER[hash(n…)]`) for ALL strip positions, including the rows that were on screen when SPIN was pressed. At `pos = 0` (also for the reels still waiting for their stagger delay) the first drawn frame therefore showed 15 different symbols (`BEFORE TOMB,CHEST,LANTERN | …` → `FIRST TOMB,LANTERN,LANTERN | BLASTER,SCATTER,KEY | …`). The engine result was never drawn early; the strip simply was not seeded with the displayed column.
**Fix (`src/view/reels.ts`):** displayedGrid = `cells` (changes only when a reel stops), targetGrid = `outcome.grid` (read only to build the strip's last 3 symbols), reelAnimationState = `Strip{plan,pos,speed}`. Strip = [displayed column] → cosmetic ordinary symbols → [target column]. The old win highlights/lines now fade out over 0.18 s instead of vanishing on click, blur filler never contains WILD/SCATTER/CHEST_BONUS (no fake bonus hints), reels always stop left→right.
**Evidence:** `tests/reels-continuity.test.ts` runs the real `Reels` at 60 fps with a recording canvas: first frame after click == last static frame (15 symbols, same y); every frame is the previous column shifted down (no replacement); last animated frame == first static frame == engine grid; **100 consecutive engine spins** (incl. Quick Spin) pass; blur contains no special symbols; browser frame captures in `05-docs/screenshots/v4/`.

## 1. Anticipation / suspense
`src/view/reels.ts` + `src/config/reelAnim.ts` + `bonusCinematic.suspense()`.
Rule: reel *c* gets a suspense phase only if, among the reels already revealed (columns < c), exactly 2 SCATTER (or 2 CHEST_BONUS, base game only) are visible — the decision never reads reel *c* itself, so hit and miss have identical timing (tested to ±1 frame). Suspense = the same continuous motion decelerating V → crawl → soft settle (velocity continuous, no jumps), ≈ +1.0 s (reel 1), +0.8 s, +0.65 s worst case < 3.2 s total; Quick Spin halves it; `prefers-reduced-motion` removes the extra time and motion effects. Visuals follow the real reveal: progressive violet (scatter) / gold (chest) glow, brighter frames, light sweep, rising spectral/gold particles, chest jitter, frame glow (`.bc-glow.hold`), tint of the suspense reel. Third symbol: controlled flash (0.32 s) + particles + highlight → existing cinematic; no third symbol: effects fade (0.35 s). Both kinds possible → combined violet/gold; both actually completed → one combined cinematic (engine `DUAL_BONUS_TRIGGERED`).
Deterministic first-spin seeds (DEV `?qa&seed=N`): plain 1 · scatter miss 11 · scatter hit 551 · chest miss 6009 · chest hit 32195 · both possible, both miss 3078 · dual hit 18682.

## 2. Control bar 0.9 and numeric centring
`src/layout.ts`: `CONTROL_BAR = {scale:.9, anchorX:960 (centred), anchorY:780 (top of the stone ledge, just under the reels)}`; `bx/by` map the old coordinates; `PANEL` and every control (SPIN, ±, info, menu, Quick Spin, fields) derive from the same transform — no per-control scale. Quick Spin tooltip, Buy Bonus widget, Skull anchor, seeker/crate waypoints were re-anchored (not scaled). Hit areas still equal the visible art (real mouse clicks at the hit centres: +, −, quick, info, menu, SPIN all work at 1920×1080, 1280×720, 1366×768, 844×390 @2x, 1280×720 @2x).
Fields (`FIELD_ART` = measured pill recesses in control-panel.png: balance 335–555×404–475, bet 674–803×404–463, win 1564–1832×404–475) are centred with flex + `line-height:1` + ONE optical correction derived from the font metrics (`ui/hudFields.ts`, `--ink-dy`, x-height band of the digits; Georgia has old-style figures) + width fitting (font shrinks if a value would touch the frame). Measured (screenshot ink boxes): horizontal error ≤ 0.4 px; vertical ≤ ±1 px for x-height digits, ≤ 2.8 px worst case for strings with old-style descenders (3,4,5,7,9) — inherent to the font, same shift for every field.
